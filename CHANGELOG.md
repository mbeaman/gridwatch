# Changelog

All notable changes to gridwatch. One minor version per arc (see `docs/ROADMAP.md`).

## [Unreleased]
### Added
- Arc 9a — the parts of shipping this machine can prove (2026-09-02, brief `docs/briefs/arc-9.md`, D59): **one table for the keys.** The list of global bindings lived in three places — the key bar's hard-coded string, the `?` overlay's array beside it, and §10's prose — and nothing kept them equal. `gridwatch-ui::keys::GLOBAL` is the source of truth for all three, and `gridwatch keybindings` writes **`docs/KEYBINDINGS.md`** from it joined with every component's `Manifest.keys`, drift-checked like the metric catalogue. It also closes an arc-1b review item open since v0.1.0: the key bar is a list, so below ~118 columns it drops whole entries instead of clipping mid-word, and the `?` overlay groups by where each key applies and says how many it could not fit. **`gridwatch theme import`** turns an alacritty or wezterm `[colors]` table or a base16/base24 scheme into a gridwatch theme — the base16 reader is thirty lines rather than a YAML dependency — deriving the roles a foreign scheme cannot carry (muted and ghost text, the panel lift), then **loading what it wrote** and printing the WCAG contrast report, so a scheme that cannot make readable muted text says so at import. It writes a file and never applies one. **The documentation a stranger needs**: `ADDING-A-COMPONENT.md` (written by following §15 against `sensors`, which turned up two wrong claims about the real API), `LAYOUT.md`, `CONTRIBUTING.md`, and a generated `THIRD_PARTY.md` built from the graph a Linux release build actually pulls — normal edges only, which is how it can say that the LGPL crate `cargo deny list` reports never enters a Linux build. The README's embedded frame is generated too: it had spent three arcs showing four shipped tiles as "arrives in a later arc". **Benches** (criterion, `cargo bench -p gridwatch-app`) for `Store::apply`, `resample`, a whole uncached frame and a theme load, with baselines in `PERFORMANCE.md` — and deliberately **not** a commit gate, because a timing assertion on a machine that may be running a game is a flake generator.
- Arc 8b — the plugin host, wired in (2026-09-02, brief `docs/briefs/arc-8.md`, D58 amendments 17–31): **`[[plugins]]`** starts a program per entry (`id` + `argv`, never a shell string, plus `rss_mb`, `cpu_secs`, `hello_ms`, `render_ms`) and registers what it declares as a placeable kind, `<id>.<the kind its manifest declares>`. Startup spawns every plugin and then waits on them together, so N plugins cost the longest `hello_ms` (2 s default) rather than the sum, and one that never answers keeps running as a source with its tile chipped "this plugin sent no manifest". A plugin's samples are an **ordinary `Batch`** on the data channel under its own `SourceId` and its `status` an ordinary `ControlMsg::Status` — the path every source already uses, so recording and `--replay` work with no plugin-specific code; its tile is an ordinary component that draws the last tree it was sent through the theme's own renderer, and a new tree raises a redraw rather than waiting for the heartbeat. **What bounds a plugin**: no shell, `env_clear`, a 1 MiB line cap, `RLIMIT_AS`/`RLIMIT_CPU`, three strikes, a **64-deep drop-oldest queue**, a **500 messages/s read budget** (over it the host simply stops reading, the pipe fills and the child blocks — measured, a flooding plugin went from costing the host 62 % of a core and 578 000 wake-ups a second to 0.97 % and 35), a **runaway check** that stops a plugin holding 50 % of a core for ten seconds, and **256 distinct metric names** per plugin. `gridwatch config check` starts the configured plugins and prints the manifests it would accept; `gridwatch shot --config DIR` renders a config directory, plugins and all, without a terminal (no flag, and a shot is byte-deterministic exactly as before); `--replay` starts none, because a replayed frame has to come from the journal alone. `docs/PLUGINS.md` is written for someone who has never read this repo, `plugins/examples/weather.py` is a source *and* a component in 140 lines of dependency-free Python, and pty C.28/C.29 run both of those claims in a real terminal. **P22** is the new ceiling.
- Arc 8a — the tools finished, and the first actions that change the machine (2026-09-02, brief `docs/briefs/arc-8.md`, D58): **the executor** — `Command::Run` has been in the component contract since arc 1 and nothing handled it; now one thread runs actions in arrival order, answers with `ControlMsg::Done` on the control channel the loop already drains, survives a panicking action, and refuses anything under `--readonly` with a sentence saying what it would have done. Confirmation is the shell's: a one-line bar under the key bar takes `y`/`Enter` to run and any other key to cancel, and it owns the next keystroke so `q` cannot quit past a question. **The four process actions** — signal, renice, affinity and I/O priority — are data built by the component (`ui::actions::ProcAction`) and executed by a handler in `app` beside the existing libc seam; `EPERM` reads "not yours to change", `ESRCH` "it exited first", and pid 0, pid 1 and gridwatch itself are refused outright. A **pid fence** (`GRIDWATCH_ACTION_ALLOW_PIDS`) makes "no test touches a process it did not spawn" a rule the executor keeps. **htop's `full` tier** (zoom-only, 100×24): Main and I/O screens as tabs, `/` search that jumps the cursor, `\` filter, `t` tree, `Space` tags with `U` to clear, `F` follow, `K`/`H` thread toggles, the F-key bar, and the three pickers (`F9` signal, `a` affinity, `i` I/O priority) — an action applies to the tag set when there is one, else to the cursor's row. **The gpu `full` tier** gains `h`/`l` column scrolling (four at a time, `PID` and `Command` pinned) and its own `F9` menu. The cpu source reads `/proc/<pid>/io`'s block-layer counters at **`Detail::Columns`** — the first user of that level — and marks the rows it could not read rather than showing zeroes; 3.5 ms over 638 processes, inside P15. Pty C.26/C.27; the htop and nvtop PARITY rows for search/filter/tree/tags/follow/screens/actions are ticked with their deviations written down.

### Added
- Arc 7b — alert rules (2026-09-02, brief `docs/briefs/arc-7.md`, D57): **`[[rules]]`** turns any metric into an alert. A rule names a key (with an optional label glob — `sensor.temp_c{nvme*:Composite}` is one rule per drive, raising one alert each), an operator (`> >= < <= == !=`, or `absent` for a key that stopped arriving), a threshold that may be a **number or another metric** read at the same label (a drive against its own `sensor.crit_c`), a `for_s` hold before it raises and a `clear_s` hold before it resolves, a severity and a message with `{key} {label} {value} {threshold} {op}` substituted. Rules are evaluated inside `Store::apply` over the scalars a batch carried — never a scan of the store — so a rule's alert is an ordinary alert: the banner, the alerts tile, `a` and `A` work on it unchanged. `gridwatch config check` lists every rule in the engine's own words and names the ones that did not parse; `config.toml` ships four commented examples (a hot GPU, a drive over its own limit, a link that went quiet, swap in use). Ten rules over a forty-sample batch cost 24 µs (P18), and a config with no rules costs nothing.
