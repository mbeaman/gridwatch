Both Records carry a journal `decode` and an exemplar in `store/tests/journal.rs`. `keys/sensors.rs`, `SOURCE = SourceId("sensors")`: `sensor.temp_c{chip:label}` (the *same* name the cpu source used — `Label::Name("k10temp:Tccd1")`), `sensor.max_c{chip:label}`, `sensor.crit_c{chip:label}` (published once per generation when the chip exports them), `sensor.fan_rpm{chip:label}`, `sensor.volt_v{chip:label}`, `sensor.power_w{chip:label}` (RAPL `package-0` when readable), `sensor.info` (Record `SensorsInfo { chips: Vec<ChipInfo { name, path, kinds: Vec<String> }>, rapl: RaplState /* Ok | RootOnly | Absent */ }`).
2. **The audio source (`sources/audio/{mod,capture,dsp,sink,supervise}.rs`, feature `audio`; `audio-lufs` adds `ebur128`).** `[sources.audio]` (§9): `sink = "auto" | "<node.name>" | <object.serial>`, `latency = 1024` (clamped 256–4096), `low_latency = false`, `fft = 2048`, `fft_bass = 8192`, `lo_hz = 30`, `hi_hz = 16000`, `floor_db = -65`, `tilt_db_oct = 4`, `fps = 30` (clamped 5–60). Cadence `Cadence { hidden: None, visible: 1000/fps, focused: 1000/fps, always_on: false }` — but the loop is **data-driven**: the io thread (`gw-audio-io`) blocks on the child's stdout and pushes f32 frames into an `rtrb` SPSC ring (8192 frames/channel); the source thread (`gw-audio`) wakes on the fps grid, drains the ring into per-channel history, runs the DSP and emits one batch. **Capture** (`capture.rs`): `pw-record --format f32 --rate 48000 --channels 2 --raw --latency <n> --target <auto|name|serial> -P '{ stream.capture.sink = true, node.passive = true, node.name = "gridwatch audio", application.name = "gridwatch" }' -` exactly as MACHINE.md verified; an explicit sink adds `node.dont-fallback = true`; `low_latency` wraps in `stdbuf -o0` with `--latency 256` **only while the source is `Visible`/`Focused`**. **Supervisor** (`supervise.rs`): spawn on the first non-`Hidden` demand; respawn only on EOF/exit (backoff 250 ms → 5 s, doubling); **never** on "no data" (`node.passive` on an idle sink delivers nothing); kill 10 s after the demand drops to `Hidden`; `pw-record` missing on PATH → `Unavailable("pw-record not found", hint: "install pipewire-bin")`; no `$XDG_RUNTIME_DIR/pipewire-0` → `Unavailable` with the socket hint; the child's stderr is read on the io thread and logged at `warn`. **Silence rule:** > 250 ms without a frame, or RMS below `floor_db` for 500 ms, ⇒ `audio.level.silent = true`, the DSP publishes at **2 Hz** (bars decay in the component) and `audio.bands` is still emitted (zeros) so tiles never freeze; a frame above the floor returns to `fps` within one tick. **DSP** (`dsp.rs`, pure, unit-tested): Hann-windowed `realfft` at `fft` for bins ≥ 250 Hz and at `fft_bass` for bins below (cava's dual FFT), amplitude `|X|·2/Σw` → dBFS, 64 log-spaced bands between `lo_hz` and `hi_hz` (edges `f_k = lo·(hi/lo)^(k/64)`; a band narrower than a bin interpolates between its neighbours), max per band, `+tilt_db_oct` per octave above 1 kHz, height `clamp((db − floor)/(0 − floor), 0, 1)`; no per-frame allocation (scratch vectors from `make_input_vec`/`make_output_vec`); the scope is the latest 512 mono samples; RMS over 300 ms, sample peak with a 1.5 s hold and 20 dB/s decay. Ballistics are the **component's** (seam 4): the source publishes instantaneous heights. **Sink enumeration** (`sink.rs`): `pw-dump` JSON (≈ 10 ms) parsed with `serde_json` for `PipeWire:Interface:Node` objects with `media.class == "Audio/Sink"` (`node.name`, `node.description`, `object.serial`, `info.state`) and the `default` metadata's `default.audio.sink`; run at start and every 2 s **while a picker is open or the sink name is on screen** (the component asks with `Control::SetOption("enumerate", true|false)`); `Control::Domain(SetSink(String))` restarts the child on the new target and republishes `audio.sink`. `Control::SetOption("fps", n)` is honoured live. **Never** `pactl`/`parec` (absent), never cpal/pipewire crates (D17/WORKSPACE bans: headers missing).

## Gotchas already verified — do not rediscover
`pw-record` 1.6.2 has no `-C`; `-P '{ stream.capture.sink = true }'` with `--target auto` follows default-sink changes by itself (WirePlumber `follow-default-target`). An unresolvable `--target` silently falls back to the default source — add `node.dont-fallback = true` when the user pins a sink. `node.passive = true` on an idle sink delivers **nothing** (not zeros): "no data" is silence, never a restart. `--latency 1024` and `100ms` both give 512-frame chunks every ~10.6 ms (stdio block buffering); `stdbuf -o0 … --latency 256` gives 256-frame chunks every 5.3 ms but forces the graph quantum down — never below the running quantum, never by default. `pw-dump` is ~280 KB/10 ms; `wpctl status` ids are **not** serials; `pw-metadata -m` is block-buffered when piped. `realfft` output is unnormalised (`·2/Σw` for a full-scale sine → 1.0) and `make_*_vec` scratch avoids per-frame allocation. hwmon numbering changes across boots; nvme `temp2_max = 65261850` is a sentinel; `asus` has no attributes; there are no `fan*`/`in*`/`power*` files and no `thermal_zone*` on torch; `energy_uj` is root-only (0400) and `perf_event_paranoid = 4` blocks the perf path — the udev rule is the documented fix. `Vec32` is `Arc<[f32]>` (the store keeps a short ring per Vector key, latest plus a few). The frame loop already parks on `1000/effective_fps` while `animated_visible()` (4b) — seam 5 only changes what feeds those two functions. `RedrawPolicy::Animated { fps: u8 }` exists in the contract since arc 1a.
