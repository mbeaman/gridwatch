## Seam decisions made in this brief (D56) — implement as written, escalate if they do not fit

1. **Keys (`keys/media.rs`, `SOURCE = SourceId("mpris")`).**
   - `media.now` — Record `NowPlaying { player: String, identity: String, title: String, artist: String, album: String, url: String, status: PlayStatus (Playing|Paused|Stopped), pos_us: i64, read_at: Ts, len_us: Option<i64>, rate: f64, volume: f64, caps: Caps { play_pause, next, prev, seek, control } , track: u64 }`. `track` is `hash(title|artist|album|url)` — the identity a tile uses to notice a change without comparing strings; `read_at` is the run-clock instant `pos_us` was read at, so the tile interpolates (`pos = pos_us + (now − read_at) × rate` while Playing) instead of asking for a faster poll.
   - `media.players` — Record `Players { list: Vec<PlayerInfo { bus: String, identity: String, status: PlayStatus, is_current: bool }> }`, republished on discovery changes.
   - `media.art` — Record `Art { track: u64, w: u16, h: u16, rgb: Vec<u8> }` (RGB8, ≤ 256 px on the long side). Decoded on the source's blocking thread, never on the render thread. Absent until decoded; a track with no art publishes nothing (the tile draws the skin).
   - `media.history` — Record `History { tracks: Vec<HistoryItem { track: u64, title: String, artist: String, at: Ts }> }`, the last 50 distinct tracks (the `full` tier's playlist).
   - `media.pos_pct` — Scalar 0..100, published with `media.now` so a replay of a journal can draw a posbar without interpolating a Record's internals.
   Every Record carries a journal `decode` and an exemplar in `store/tests/journal.rs`. `Art.rgb` is journalled base64-free (a `Vec<u8>` serialises as a JSON array — acceptable at ≤ 256×256×3 for a fixture, and `--tables off` does not gate it; if a recording proves it heavy, D56 gets an amendment, not a silent format change).
2. **The `mpris` source (`sources/mpris/{mod,proxy,discovery,player,art}.rs`, feature `mpris`).** One `current_thread` tokio runtime on a **private thread** (`spawn_async_runtime`, §4.3) — tokio never touches the render thread. Hand-rolled zbus 5 proxies (`proxy.rs`): `org.mpris.MediaPlayer2` (`Identity`, `Raise`, `CanRaise`) and `org.mpris.MediaPlayer2.Player` (`PlaybackStatus`, `Metadata`, `Position` with `emits_changed_signal = "false"`, `Rate`, `Volume`, `CanControl`/`CanGoNext`/`CanGoPrevious`/`CanSeek`/`CanPause` as consts, methods `PlayPause`/`Next`/`Previous`/`Stop`/`Seek`/`SetPosition`). **Discovery** (`discovery.rs`): `ListNames` once, then `NameOwnerChanged` with an `arg0namespace='org.mpris.MediaPlayer2'` match so the bus filters for us. **Per player** (`player.rs`): a task with `select!` over the properties-changed stream, the `Seeked` signal, owner-changed, a 1 Hz `Position` poll **only while Playing**, and the command channel. **Choice of current player:** Playing > most recently changed > alphabetical by bus name; `p` cycles and pins a choice until that player goes away. **Commands** arrive as `Control::Domain(Box<MediaCmd>)` — `MediaCmd { PlayPause, Next, Prev, Stop, SeekBy(i64 µs), SetVolume(f64), Raise, Pick(String) }` — declared in **`store::keys::media`** (D55 amendment 1's rule: components box it, sources downcast). **Art** (`art.rs`): `file://` read, `https://` through `ureq` (5 s timeout, 8 MB cap, no redirect chains beyond 3), `data:` decoded inline; then `image` 0.25 → RGB8, downscaled so the long side ≤ 256 px, published as `media.art`. Fetch and decode run on a **blocking task** (`spawn_blocking`), never in the select loop. A failed fetch is a `debug!`, never a status change. `[sources.mpris]` (§9): `player = "auto" | "<bus suffix>"`, `art = true`, `art_max_px = 256`, `poll_ms = 1000` (clamped 250–5000), `history = 50`. Degraded: `DBUS_SESSION_BUS_ADDRESS` unset ⇒ `Unavailable("no session bus", hint "start a session bus or run inside your desktop session")`; bus present but no player ⇒ `Ok` with reason `no player` (not Degraded — nothing is broken).
3. **The `winamp` component (`components/winamp/{mod,view,marquee,art}.rs`, feature `mpris`).** Manifest `sources = [mpris]`, `optional_sources = [audio]`, `requires: []`, `optional: [DbusSession]`, `chrome: Chrome::Custom` (the tile paints its own frame through theme roles — no shell block), default footprint 4x2, footprints 1x1 / 2x1 / 4x2 / 6x3. `RedrawPolicy::Animated { fps: 10 }` **while a marquee is scrolling or the position is advancing**, `Redraw::No` when Paused/Stopped and the marquee fits (the 5a rule: the tile earns its frames). Tiers: `status` 8×3 [`▶`] — the play glyph, a one-line marquee and a two-cell posbar; `shade` 24×3 [`:`] — + `1:23/4:56` and an 8-bar mini vis from `audio.bands` (a static skin when the audio source is absent); `main` 40×10 [`kbps`] — + `tui-big-text` Quadrant digits for the elapsed time, the marquee stepping at 220 ms from `cx.now`, `128 kbps · 48 kHz · stereo` from `audio.sink`, the 19-band vis, the posbar, the volume slider, the transport row with unsupported actions in `TextGhost`; `main+art` 60×12 [`art`] — + the album art through the in-tree halfblock widget (`▀` with fg/bg per cell pair, `View::Custom` painting through theme roles only); `full` 100×24 zoom-only [`playlist`] — + the EQ curve weighting the vis and the playlist from `media.history`. Keys once captured: `x` play, `c` pause, `v` stop, `b` next, `z` previous, `←/→` seek ∓5 s, `+/-` volume, `p` cycle player, `r` raise. Empty store: the idle skin with `no player`. Components never touch D-Bus.
4. **The halfblock art widget (`ui/src/halfblock.rs`).** `paint(rgb: &Art, area, theme, buf)`: two vertical pixels per cell as `▀` with the top pixel's colour as fg and the bottom's as bg, nearest-neighbour scaled to the rect, and — because a component may not name a colour (§4.6) — it is a **ui-crate widget the theme's renderer owns**, reached from the component as `View::Custom { paint, describe: "album art" }` where `paint` is a `Box<dyn Paint>` the ui crate constructs. In `ColorMode::Ansi16`/`Ansi256` the widget quantises through the theme's palette; in `mono` it draws the theme's `TextMuted` block shades by luminance. Never a new `View` variant.
5. **Marquee and time (`marquee.rs`, pure).** `step(text, width, now) -> &str` — one character per 220 ms from `cx.now` (virtual under replay, so a shot is deterministic), the Winamp separator `  ***  `, no scroll when the text fits. The elapsed clock is `pos_us` interpolated from `read_at` at the tile's fps; `len_us == None` ⇒ **stream mode**: the elapsed clock counts from the first `read_at` of this `track` and the posbar draws the Winamp "stream" pattern instead of a fill.
6. **Fixtures and tests.** `fixtures/mpris/` holds recorded `a{sv}` metadata dictionaries as JSON (from `busctl --user --json=short get-property … Metadata` on torch: a YouTube page in Firefox with `mpris:length`, a live stream without it, a player with `xesam:artist` as a one-element array, one with no art, one with a `data:` art URL) plus the `PlaybackStatus`/`Position`/`Rate` values beside them; `proxy.rs`'s decoder is a pure function over the parsed `a{sv}` shape and every fixture is a test. The player task is tested over a **fake bus**: a trait `Bus` with `properties_changed()`, `seeked()`, `get(prop)` and `call(method)` that the tests drive with a scripted stream, so discovery, the current-player choice, the 1 Hz poll gating, stream mode and command dispatch are all covered without D-Bus. One `#[ignore]` live test (`live_mpris_lists_players`) reads the session bus and prints what it found — `busctl` is a safe probe, but an agent never starts or controls a player.
7. **Shell.** No new seam: `Command::Source(mpris, Control::Domain(MediaCmd))` already routes (D50 §6), `Animated` already drives the frame clock (D55 seam 5). The `sources` tile prints the mpris source's `art 12 ms` / `poll 1 Hz` note from `media.now`'s cadence.
8. **`gridwatch doctor`.** `Capability::DbusSession` is probed already; the source's `doctor()` adds a live row (the bus answers `ListNames`, the players found) behind the live flag — the session bus is not a sysfs read, so it stays out of `doctor_offline()`.
9. **Performance rows.** P12 (the winamp tile idle ≤ 1 % of one core; the marquee at 10 fps costs ≤ 0.5 % more), P19 (art fetch+decode ≤ 150 ms wall for a 1 MB PNG, never on the render thread; the tile's first paint of a new track ≤ 1 frame after `media.art` lands) — measured under `--demo` with the synth player, and live with Firefox **by Matt** (an agent does not start players; the demo synth carries an embedded PNG so the art path is exercised headlessly). ## Gotchas already verified — do not rediscover
Firefox exports `org.mpris.MediaPlayer2.firefox.instance_1_107` (the instance suffix changes per process); on torch a YouTube tab gives `xesam:title`, `xesam:artist` as a **one-element `as`**, `xesam:album` as an **empty string**, `mpris:artUrl` as a `file://` PNG under `~/snap/firefox/common/.mozilla/firefox/firefox-mpris/`, `mpris:length` in **microseconds** (`7170000000` = 1 h 59 m) and `mpris:trackid` as an **object path**, not a string — decode it as either. `Position` is `x` (µs) and does **not** emit changes; a multi-element page can report `Position = 0` forever (the digest's stream-mode fallback). `PlaybackStatus` is `Playing|Paused|Stopped`; `Rate` and `Volume` are doubles. `busctl --user` and `busctl --user --json=short` are the safe probes. zbus 5 with `default-features = false, features = ["tokio"]` avoids async-io; the `mpris` crate (libdbus) and `ratatui-image` stay banned (`deny.toml`).
