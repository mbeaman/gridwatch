## Seam decisions made in this brief (D47) — implement as written, escalate if they do not fit

1. **Journal line format (§4.5).** JSON Lines, one object per line, `t` = `Ts` nanoseconds since the run epoch:
   ```
   {"v":1,"wall_epoch":1756700000,"host":"torch","size":[250,70],"sources":["cpu","gpu"]}      header
   {"t":1500000000,"b":{"src":"cpu","s":[["cpu.core_pct{3}",12.5],["cpu.breakdown{3}",{"nice":0.0,…}],["audio.bands{0}",[0.1,0.2]]]}}
   {"t":1500000000,"st":{"src":"cpu","state":"Ok","reason":null,"hint":null,"dropped":0,"restarts":0}}
   {"t":1500000000,"al":{…AlertEvent as serde…}}
   {"t":1500000000,"in":{…InputEvent as serde…}}                                                only with --record-input
   ```
   A sample is `[name_with_label, datum]`; the datum's JSON *type* decides its kind on read — number → `Scalar`, array → `Vector`, object → `Record` revived through `KeyMeta::decode`. The name is interned onto the static catalogue via `lookup(name)`; an unknown name is skipped with one warning per name per file. Labels parse back from `{n}` / `{text}`. `--tables off` (the default) omits samples whose key is `proc.table` or `gpu.procs`.
2. **Replay is a source (§4.3).** `JournalSource` implements `Source`: it owns the file, and on each line it advances the shared `Clock::Virtual` to `t` (sleeping `(t − prev)/speed` of wall time in between; `--speed 0` = as fast as possible) and re-emits the line through the normal channels — batches on `data`, statuses/alerts on `control`, inputs on `input`. The rest of the app cannot tell replay from live; that is the point. A replay run registers *only* the journal source; the registry's real sources are not started.
3. **The recorder is a tee in the frame loop (§4.2).** Every `Msg` the loop drains is also sent on a bounded channel to a `gw-record` writer thread (`BufWriter`, flushed every second and on quit). A full channel drops the message and counts it in the HUD; recording must never stall a frame.
4. **GPU keys, all labelled `{dev}` (§4.1, `keys/gpu.rs`, `SOURCE = SourceId("gpu")`):**
   `gpu.util_pct` `gpu.memctl_pct` `gpu.vram_used_b` `gpu.vram_total_b` `gpu.power_w` `gpu.power_limit_w` `gpu.power_trace` (Vector, W at 20 ms) `gpu.temp_c` `gpu.temp_slowdown_c` `gpu.fan_pct{dev:i}` `gpu.fan_rpm{dev:i}` `gpu.clock_gfx_mhz` `gpu.clock_mem_mhz` `gpu.clock_gfx_max_mhz` `gpu.clock_mem_max_mhz` `gpu.pcie_rx_bps` `gpu.pcie_tx_bps` `gpu.pcie_gen` `gpu.pcie_width` `gpu.enc_pct` `gpu.dec_pct` `gpu.pstate` (0–15, 32 = unknown) `gpu.throttle` (Record `Throttle { bits: u64 }`) `gpu.info` (Record `GpuInfo`) `gpu.procs` (Record `GpuProcs`).
   `GpuInfo { name, driver, cuda, arch, uuid, pci_id: u32, bus_id, vbios, cores: Option<u32>, bus_width: Option<u32>, spec: Option<GpuSpec> }`; `GpuSpec` is the hand-verified const row (`sms, tmus, rops, rt_cores, tensor_cores, l2_mb, base_mhz, boost_mhz, mem_gbps, bandwidth_gbs, tdp_w, die_mm2, transistors_b, launch: &'static str`) keyed by PCI device id — **`0x2B85` is the 5090** (gpuwatch's DB maps it to a 5070; do not copy that file). Effective load (`util × power/limit`, nvtop's `extract_gpuinfo.c`) is computed in the component, not published.
   `GpuProcRow { pid, kind: Graphics|Compute|Both, vram_b: Option<u64>, sm_pct, mem_pct, enc_pct, dec_pct, fresh }` and `GpuProcs { rows: Vec<GpuProcRow>, vram_total_b }` exactly as §8.1; `ProcRow`/`ProcTable` already exist in `keys/cpu.rs`.
5. **Cargo features arrive now** (the BACKLOG item, WORKSPACE.md's plan): `gridwatch-sources` features `cpu` (default) and `gpu` (default, pulls `nvml-wrapper`); `gridwatch-components` features `htop`, `gpu`; the `gridwatch` bin re-exports them; `builtin_*` registration under `#[cfg(feature)]`; CI's feature matrix checks each alone. `deny.toml` stays as is — `nvml-wrapper` is MIT/Apache and `libloading` is ISC (already allowed).
6. **Two new components declare `signature(tier)`** (D46) and are covered by `assert_renders_everywhere`, the app lattice and the pty suite (`--demo` must draw both tables; `--replay fixtures/journals/torch-idle.jsonl --speed 0` must reach a frame).

## Gotchas already verified — do not rediscover
`libnvidia-ml.so.1` exists, bare `.so` does not (nvml-wrapper dlopens `.so.1` — fine). Driver 610 uses `FieldIdScheme::V13Update1`; the crate translates. `memory_info` v2 `used` excludes reserved; nvtop's MEM bar is `used/total` VRAM, not `utilization_rates().memory`. `temperature_threshold(Slowdown)` = 93 works; the TLIMIT fields return *margins*. `applications_clock`/`max_customer_boost_clock` → `NotSupported`, and `NVML_FI_DEV_MEMORY_TEMP` costs 1.2 ms to say `NotSupported` — never poll it. `process_utilization_stats` works unprivileged on GeForce; count query says capacity 72, real results 1–2. `samples(Power)` = 119 samples at 20 ms; `samples(ProcessorClock)` count succeeds but the fetch is `NotSupported`. Fan speed is the setpoint. nvtop's TYPE is never `Both` on the NVIDIA backend — gridwatch merges, PARITY says so. `/proc/1/io` is root-only: never in the pid-level scan. CPU% period uses `active_cpus` (online), not `nproc`. `script` buffers — pty tests need `-f`. The store's `Vector` series keep 64 entries: the 20 ms power trace is one `Vec32` per slow tick, not one sample per 20 ms.
