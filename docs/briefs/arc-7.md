## Seam decisions made in this brief (D57) — implement as written, escalate if they do not fit

1. **Keys (`keys/net.rs`, `SOURCE = SourceId("net")`).** Per interface, labelled by name: `net.rx_bps{iface}`, `net.tx_bps{iface}`, `net.rx_pps{iface}`, `net.tx_pps{iface}`, `net.rx_drop{iface}`, `net.tx_drop{iface}` (deltas per second), `net.rx_err{iface}`, `net.tx_err{iface}`, `net.speed_mbps{iface}` (−1 unknown), `net.link{iface}` (Record `Link { up: bool, carrier: bool, operstate: String, mtu: u32, mac: String, kind: LinkKind (Ether|Wifi|Loopback|Virtual|Tun|Other), speed_mbps: i64, carrier_changes: u64, addrs: Vec<String>, wifi: Option<WifiInfo { ssid: String, signal_dbm: i32, freq_mhz: u32, rx_bitrate_kbps: u32, tx_bitrate_kbps: u32 }> }`), `net.route` (Record `Route { default_iface: String, gateway: String, prefsrc: String, dns: Vec<String>, public_ip: Option<String> }`), `net.conns` (Record `Conns { rows: Vec<Conn { proto, local, remote, state, inode, pid: Option<u32>, uid: u32, process: String }>, scanned: usize, attributed: usize, scan_ms: f64 }`), `net.rtt_ms{target}` and `net.loss_pct{target}` plus `net.probe` (Record `Probes { targets: Vec<ProbeStat { target, kind: Icmp|Tcp, min_ms, avg_ms, max_ms, mdev_ms, jitter_ms, loss_pct, sent: u64 }> }`), and `net.scan_ms` (the connection scan's cost, the `sources` tile's note). Records carry journal `decode` and exemplars.
2. **The `net` source (`sources/net/{mod,dev,link,route,conns,probe,wifi}.rs`, feature `net`; `net-probe` adds the latency probes, `net-wifi` the nl80211 path).** Cadence 1 s at every level, `always_on: false`. **Counters** (`dev.rs`): one read of `/proc/net/dev` per tick, split on the **first colon** (names longer than six characters butt against it), rates from the previous sample with `saturating_sub` over the measured `dt`, state keyed by `(name, ifindex)` so a re-created veth resets cleanly. **Link** (`link.rs`): `/sys/class/net/<if>/{operstate,carrier,speed,duplex,mtu,address,type,flags,carrier_changes}` every 2 s (not every tick); a `speed` that is negative or unreadable is *unknown*, never a number; `wireless`/`phy80211` presence is the Wi-Fi detector; addresses from `getifaddrs` through `nix` (feature `net`). **Route** (`route.rs`): `/proc/net/route` (`destination == 0` and `RTF_GATEWAY`, lowest metric; little-endian hex), IPv6 from `/proc/net/ipv6_route`; DNS from **systemd-resolved over zbus** when the `mpris` runtime is already there (arc 6 brought zbus in) with `/etc/resolv.conf` as the fallback, labelled "via systemd-resolved" when it is the stub. **Connections** (`conns.rs`, `Detail::Table` only): `/proc/net/{tcp,tcp6,udp,udp6}` parsed in-tree (little-endian hex addresses, big-endian ports, the `st` table), joined with an inode → pid map from `/proc/*/fd` on a **blocking helper thread** at 2 s while the table is visible; sockets whose owner is unreadable show their uid. **Probes** (`probe.rs`, feature `net-probe`): unprivileged `SOCK_DGRAM` ICMP (verified working on torch: 1.4 ms to the gateway) with a **TCP-connect fallback** when the socket is refused, 1 Hz, a 60-sample ring per target (min/avg/max/mdev, RFC 3550 jitter, loss %); targets default to the gateway plus `1.1.1.1`; `[sources.net] probes = []` turns them off. **Wi-Fi** (`wifi.rs`, feature `net-wifi`): `neli-wifi` for SSID/dBm/bitrate, NetworkManager over zbus as the fallback, `/proc/net/wireless` last. `[sources.net]`: `refresh_ms = 1000` (clamped 250–10000), `link_ms = 2000`, `conns = true`, `conns_ms = 2000`, `probes = ["gateway", "1.1.1.1"]`, `probe_ms = 1000`, `public_ip = false` (opt-in, at most every 15 minutes, with the privacy note in the config comment). **Public IP is off by default and never fetched without it.**
3. **The `net` component (`components/net/{mod,view,model}.rs`, feature `net`).** Manifest `sources = [net]`, `optional: [PingSocket, NetRaw]`, default footprint 4x2, footprints 1x1 / 2x1 / 4x2 / 6x3. Instance options: `interfaces = ["en*", "wl*", "wg*", "tun*"]`, `hide = ["lo", "veth*", "br-*", "docker*", "virbr*"]`, `rdns = false`, `sort = "traffic" | "name"`. Tiers: `rates` 8×3 [`↓`] — `↓ 1.2M ↑ 340k` for the default-route interface with a link dot; `sparks` 20×5 [`↑`] — + rx/tx sparklines and the speed or SSID; `table` 48×10 [`iface`] — every shown interface as `IFACE · STATE · ↓ · ↑ · DROP · ERR`, the probe strip (`gw 1.4 ms · 1.1.1.1 12 ms · 0 % loss`); `conns` 70×16 [`conns`] — + the top connections by state with pid/process or uid; `full` 100×24 zoom-only [`route`] — + the route/DNS pane, the per-interface detail (mac, mtu, addresses, carrier flaps) and the full probe stats. Keys once captured: `a` show every interface (the hide list off), `s` cycle the sort, `c` toggle the connection table's protocol filter, `↑/↓` scroll, `r` toggle rDNS for this instance. Empty store `—`; `PingSocket` missing ⇒ the probe strip says `tcp` and why.
4. **The rules engine (`store/src/rules.rs`, seam for 7b).** `[[rules]]` entries: `name` (unique), `key` (a metric name with an optional label pattern: `sensor.temp_c{nvme*:*}`), `op` (`>`, `>=`, `<`, `<=`, `==`, `!=`, `absent`), `value` (a number **or** another key — the metric RHS), `for_s` (hold before raising, default 0), `clear_s` (hold before resolving, default = `for_s`), `severity` (`info|warn|crit`), `message` (a template with `{key}`, `{label}`, `{value}`, `{threshold}`). Rules are **name-indexed** and evaluated inside `Store::apply` on the keys a batch actually touched — never a scan of the whole store. A rule that matches several labels raises **one alert per label** (`id = "<name>/<label>"`). Hysteresis is the two holds; a rule whose key stops arriving resolves after `clear_s` unless the op is `absent` (which raises then). `gridwatch config check` validates every rule against the catalogue (an unknown key name is an error, an unknown label pattern is not) and prints what each rule would watch. Four defaults ship commented-out in `config.toml`: `gpu-hot` (`gpu.temp_c > 84 for 30s`), `cpu-hot` (`sensor.temp_c{k10temp:Tctl} > 88 for 30s`), `nvme-crit` (`sensor.temp_c{nvme*:Composite} >= sensor.crit_c{nvme*:Composite}`), `link-down` (`net.link{...}` absent or down for 10 s).
5. **Fixtures and tests.** `fixtures/net/` holds a recorded `/proc/net/dev`, `/proc/net/route`, `/proc/net/tcp` + `tcp6` + `udp`, a `/sys/class/net` tree for three interfaces (an up Ethernet, a down Wi-Fi, a bridge with no carrier) and an `ifaddrs` dump as JSON — all recorded from torch, all read-only. The parsers are pure functions over a root path (the `Roots` pattern the cpu source already uses) and every fixture is a test: the six-character name collision, a negative `speed`, a counter reset, the little-endian address decoding, the state table, an unattributed socket. The probe's ring statistics are unit-tested on a scripted sample sequence; the ICMP socket itself is a `#[ignore]` live test (`live_icmp_reaches_the_gateway`) — an unprivileged DGRAM ping is a safe read-only probe on torch, but it leaves the machine, so it stays ignored in CI. The rules engine is tested on a synthetic store: raise after `for_s`, not before; clear after `clear_s`; one alert per label; a metric RHS; `absent`; a rule that never matches costs nothing.
6. **Performance.** P13 (the net source ≤ 1 % of one core with the connection table visible; the `/proc/*/fd` scan ≤ 10 ms and only while visible), P1/P5/P6 re-taken with the source live, P19 unchanged. The `sources` tile prints `scan 3.2 ms · 87/103 attributed`.

## Gotchas already verified — do not rediscover
`/proc/net/dev` names longer than six characters butt against the colon. `speed` is `-1` on a carrier-less bridge, `10000` on veth, and `EINVAL` on a down Wi-Fi NIC. `net.ipv4.ping_group_range` on torch allows unprivileged `SOCK_DGRAM` ICMP (1.4 ms to 192.168.100.1); `SOCK_RAW` and `AF_PACKET` are `EPERM`. `/proc/net/route`'s gateway is little-endian hex (`0164A8C0` = 192.168.100.1). `/etc/resolv.conf` is the systemd-resolved stub (127.0.0.53) — the real servers come from resolved. `nsswitch` includes `mdns4_minimal`, so `getnameinfo` can stall: rDNS is async and opt-in, never on the render path. The `/proc/*/fd` scan reads 143 of 628 processes as the user (the rest `EACCES`) and attributed 87 of 103 sockets in the digest's measurement. `wlp7s0` is **down** on torch: the Wi-Fi path is fixture-tested, and its live row is owed. `nf_conntrack` has no procfs here; eBPF needs a toolchain that is not installed — per-process bandwidth stays a later arc behind a capability badge.
