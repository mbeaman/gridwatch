# Integrating astral-watch (per-pin 12V-2x6 amperage) as an opsTui component, plus a general sensors source (hwmon / RAPL / PSI) — API, consumption modes, i2c concurrency, dependency mechanics, size classes, alarm overlay

## 1. The exact public API to consume (HEAD, `astral_watch::…`)

**i2c** (`src/i2c.rs`): `CHIP_ADDR: u16 = 0x2b`, `CHIP_ADDR_STR`, `REG_BASE: u8 = 0x80`, `REDETECT_AFTER: u32 = 10`. `nvidia_buses() -> Vec<u32>` (scans `/sys/class/i2c-dev/*/name` for "NVIDIA"; on torch that is i2c-1..7, all under `0000:01:00.0`). `detect_bus(addr) -> Detect { Found(u32) | NoBuses | PermissionDenied | NoTelemetry }` — probes each bus **bytewise** and requires `Reading::plausible()`. `read_reading(bus, addr) -> anyhow::Result<Reading>` = `decode(read_raw(bus, addr)?)`; `read_raw` opens `/dev/i2c-N` **on every call** (O_RDWR, `I2C_SLAVE` ioctl, PEC off), consults a process-global `static ACCESS: LazyLock<Mutex<HashMap<(bus,addr), Access>>>` and does: `Block` → one `I2C_SMBUS_I2C_BLOCK_DATA` read of 24 bytes (re-opens the question if the result is implausible); `ByteWise` → 12 × (hi, lo, hi-confirm, up to 3 retries) = 36 transactions; `Unprobed` → bytewise reference, then a block read compared per-pin (±0.5 V) and latched (`Block`), a wrong answer latches `ByteWise` immediately, an *error* is retried up to `BLOCK_PROBE_ATTEMPTS = 3` before latching bytewise. `read_reading_bytewise(bus, addr)` bypasses the cache (for discovery). `bus_pci_id(bus) -> Option<String>` (e.g. `0000:01:00.0`), `norm_pci(&str)`, `redetect_card(addr, want_pci) -> Option<u32>` (only re-attaches to the same PCI id and calls `forget_access`). `RegReader` trait (`read_reg`, `read_block`) is the mock seam — opsTui can unit-test with a fake chip exactly like the crate's own tests.

**decode**: `PIN_COUNT = 6`, `RAW_LEN = 24`, `Pin { volts: f64, amps: f64 }`, `Reading { pins: [Pin; 6] }` (Copy) with `total_amps()`, `total_watts()` (Σ V·I), `max_volts()`, `balance() -> Option<f64>` (hi/lo, `None` when lo ≤ 0.05 A), `plausible()` (max_volts in 5..=20 V), `decode(&[u8;24])` (big-endian mV/mA pairs, stored high-pin-first, reversed to pin 1..6).

**alert**: `OVERLOAD_A = 9.2`, `IMBALANCE_RATIO = 1.5`, `MIN_LOAD_A = 5.0`, `IMBALANCE_ALARM_PIN_FRAC = 0.85`; `Thresholds { overload_amps, imbalance_ratio, min_load_amps }` (serde, `deny_unknown_fields`, `Default`); `evaluate(&Reading, &Thresholds) -> Vec<Alert>` with `Alert::{Overload{pins: Vec<usize>, limit}, Disconnected(Vec<usize>), Imbalance(f64), ImbalanceAdvisory(f64)}`; `Display` text is comma-free (`OVERLOAD pins 1+2 >9.2A`). Disconnect/imbalance only evaluated when total > `min_load_amps`; a pin < 0.1 A is `Disconnected`; imbalance is an alarm only when the hottest pin ≥ 0.85 × overload (7.82 A), otherwise advisory.

**lifecycle**: `Condition::{Overload, Disconnected, Imbalance, ImbalanceAdvisory, TelemetryLost}` with `id()` (`overload`, `imbalance_advisory`, `telemetry_lost` …), `label()` (`OVERLOAD`, `IMBALANCE (ADVISORY)`, `TELEMETRY LOST`), `advisory()`, `severity_sibling()`; `condition_of(&Alert)`; `Event::{Raised{condition, detail}, Repeated{condition, detail, active_for}, Resolved{condition, active_for}}` + `Display` (`ALERT RAISED: …`, `ALERT RESOLVED: OVERLOAD clear after 1h02m`), `fmt_duration`. `Lifecycle::new(AlertPolicy)` and `observe(&mut self, now: Instant, present: &[(Condition, String)]) -> Vec<Event>` — semantics: **raise** when the condition is present in ≥ `confirm` of the last `2·confirm−1` samples (majority window; `confirm_for(cond)` = `advisory_confirm_samples` for advisories); **resolve** after `resolve_samples` consecutive clean samples; **repeat** every `repeat_minutes` (0 = once); a `TelemetryLost` sample **freezes** every other condition (no raise, no resolve from missing data); an Active imbalance whose samples reclassify to its sibling severity is frozen instead of resolved. Defaults: confirm 3, advisory 240, resolve 20, repeat 10 min. `now` is injected, so opsTui tests are deterministic.

**config**: `config::load(explicit: Option<&Path>) -> Result<(Config, Option<PathBuf>)>`: explicit → `$XDG_CONFIG_HOME/astral-watch/config.toml` (else `~/.config/…`) → `/etc/astral-watch.toml` (`SYSTEM_PATH`) → `Config::default()`. `Config { thresholds, alerts: AlertPolicy, notify, export: Option<ExportConfig{listen}>, safety }`, all `deny_unknown_fields` — never write opsTui keys into that file; `Config::warnings()` lists loosened thresholds. **cards**: `gpu_at(pci) -> Option<GpuInfo{pci, subsystem_vendor, subsystem_device}>`, `GpuInfo::model()`/`is_asus()`, `nvidia_gpus()`, `model_for(0x8a2e) == Some("ROG Astral RTX 5090 (variant)")` — torch's subsystem 1043:8A2E is in the DB. **metrics/exporter**: `Metrics::{new, on_good_sample, on_implausible_sample, on_read_error, on_event, render}` and `exporter::spawn(listen, Arc<Metrics>) -> Result<SocketAddr>` (hand-rolled HTTP, sequential accept) — opsTui could *be* the exporter when the service is absent. **logger**: `CsvLogger::open(path, max_bytes, keep)`, `.log(ts, &Reading, &[Alert])`, `.log_unreachable(ts, msg)`; 17 columns `timestamp,p1_V,p1_A,…,p6_V,p6_A,total_A,total_W,balance,alerts`, alerts joined by `;`, timestamps local naive `%Y-%m-%dT%H:%M:%S`.

**How main.rs drives it** (`run()`): default `--interval 1.0` (service uses 0.5), warn below 0.05 s; `acquire_bus` loops `detect_bus` every 5 s feeding `TelemetryLost` into the lifecycle until `Found`; per sample: `Ok(r) if r.plausible()` → `evaluate` + sinks; `Ok(_)` → `TelemetryLost("implausible reading (chip answered; wrong device or GPU resetting?)")` (this is the **deeply idle GPU** case — the MCU answers zeros); `Err(e)` → `TelemetryLost("read failed: …")` and CSV `GPU_UNREACHABLE`; `misses >= REDETECT_AFTER` (10) → `redetect_card(addr, original_pci)`; sleep is interruptible in 200 ms steps. `tui.rs` has the same `sample()` but also `discover_cards()` (one tab per PCI id that answers bytewise) and `redetect_card` per tab.

**What tui.rs renders (parity checklist):** constants `HISTORY = 300`, `LOG_CAP = 200`, `AMPS_CEILING = 10.0`, interval clamp 100 ms–5 s, `PIN_COLORS` = Cyan/Green/Yellow/Magenta/Blue/LightRed. Layout: optional tab row; "device" header (5 rows, or 1-row compact when height < 16): line 1 badge + model + PCI + `PCIe Gen5×16` from sysfs `current_link_speed/width` (yellow + `↓` when below `max_link_*`) + `i2c-N @ 0x2b` + `⏸ PAUSED`; line 2 nvidia-smi bars `GPU ████░░ 19%`, `PWR 107/600W` (green < 85 %, yellow < 97 %, red), `45°C` (green < 75, yellow < 85, red), `fan 30%` — polled by a thread every 1.5 s via `nvidia-smi --query-gpu=pci.bus_id,utilization.gpu,power.draw,power.limit,temperature.gpu,fan.speed --format=csv,noheader,nounits`; line 3 `connector 9.2 A · 111 W · balance 1.54× · pins 12.06–12.08 V` (prefixed `STALE ·` when not live). Alarm row (only when lifecycle-active): red bg + white + BOLD|SLOW_BLINK `⚠ ALERT: OVERLOAD + DISCONNECT ⚠` for alarms; yellow bg, no blink, `IMBALANCE (ADVISORY)` when only advisories. Body ≥ 110 cols: left 58 % = custom bars (45 %) over Braille `Chart` trend (55 %); right 42 % = totals (4 rows: `9.2 A ~111 W peak 620 W`, `pins 12.06–12.08 V · samples N`), balance `Gauge` (4 rows, ratio = (b−1)/(1.5−1) clamped, NORMAL/WARN(>1.33)/ALARM(>1.5)/idle when total ≤ min_load), watts `Sparkline` (3 rows), alert log `List` + `Scrollbar`. Narrow: bars/totals/balance/log stacked. Bars: 6 slots, `█` fill by amps/10, `▔` dim white session-peak cap, red dim `┄` limit line at 9.2 A drawn only on empty cells, value `8.2` and `p1` labels; pin color red > 9.2, yellow > 7.82, dark-gray at 0 or stale, else green. Keys: q/Ctrl-C, space pause, r reset peaks, +/- rate, 1-5 zoom panel (0/Esc back), ↑↓/wheel scroll log, Tab card, ? help popup (`Clear` + centred `Flex`).

## 2. Consumption modes and the i2c concurrency question

**(a) Direct i2c (link the library).** Requires `/dev/i2c-*` access: on torch they are `crw-rw---- root i2c` and the user is in `i2c` (uid 1000 groups include 126(i2c)) — no sudo. The `i2cdev` crate opens O_RDWR, so 0660 is needed. Cost per sample: ~4 ms of kernel busy-poll on the block path, ~33 ms bytewise (crate's own measurements). **Concurrency analysis (verified against kernel v6.12 sources):** every `I2C_SMBUS` ioctl becomes exactly one `i2c_smbus_xfer()`, which wraps `__i2c_smbus_xfer` in `__i2c_lock_bus_helper(adapter)` … `i2c_unlock_bus(adapter, I2C_LOCK_SEGMENT)`; the NVIDIA adapter (`nv-i2c.c`) registers a native `smbus_xfer` that handles `I2C_SMBUS_I2C_BLOCK_DATA` and advertises `I2C_FUNC_SMBUS_I2C_BLOCK`, taking no lock of its own. So the 24-byte block read (command byte + 24-byte read) is **one indivisible bus transaction**: another process cannot interleave, and the register pointer cannot move mid-read. On the bytewise path each `read_byte_data` is itself atomic and re-sends the register address, so an interleaved reader cannot corrupt a byte — it only widens the hi→lo time window, which the hi/lo/hi tear check already guards. `i2c-dev`'s `I2C_SLAVE` returns EBUSY only if a *kernel* `i2c_client` with a bound driver owns the address (`i2cdev_check_addr` walks the adapter's registered children; anonymous i2c-dev clients are invisible), so two userspace processes (the root logger + opsTui) can both open i2c-N@0x2b. Net effect of contention: added latency and occasional EIO/timeouts, **not corrupted readings**. astral-watch mitigates by treating errors as `TelemetryLost` (frozen alerts, majority-window confirm) and by not latching the slow path on a single block-read error. Recommendation for opsTui: keep the interval ≥ 0.5 s, sample on a dedicated std thread, and drop to 1 s when the component is not visible (never stop — the alarm overlay depends on it).

**(b) Scrape the exporter.** `GET /metrics` on `127.0.0.1:9942` (HTTP/1.1, `connection: close`, text/plain version 0.0.4). Useful series: `astral_watch_pin_amps{pin="1..6"}`, `astral_watch_pin_volts{pin}`, `astral_watch_total_amps`, `astral_watch_total_watts`, `astral_watch_balance_ratio` (may be `+Inf`; absent at idle), `astral_watch_last_reading_age_seconds` (absent until a reading exists), `astral_watch_up`, `astral_watch_alert_active{condition="overload|disconnected|imbalance|imbalance_advisory|telemetry_lost"}`, `astral_watch_alerts_raised_total{condition}`, `astral_watch_samples_total`, `astral_watch_read_failures_total`, `astral_watch_implausible_readings_total`, `astral_watch_build_info{version}`. Staleness rule: treat data as stale when `up == 0` **or** `last_reading_age_seconds > 3 × interval`; treat the source as down when connect fails twice. Do not add `prometheus-parse` (pulls chrono+regex+itertools); a ~50-line parser suffices:

```rust
fn parse_line(l: &str) -> Option<(&str, Vec<(&str, &str)>, f64)> {
    if l.starts_with('#') || l.is_empty() { return None; }
    let (head, val) = l.rsplit_once(' ')?;
    let v = match val { "+Inf" => f64::INFINITY, "-Inf" => f64::NEG_INFINITY, "NaN" => f64::NAN, s => s.parse().ok()? };
    let (name, labels) = match head.split_once('{') {
        Some((n, rest)) => (n, rest.trim_end_matches('}').split(',').filter(|s| !s.is_empty())
            .filter_map(|kv| kv.split_once('=').map(|(k, v)| (k, v.trim_matches('"')))).collect()),
        None => (head, Vec::new()),
    };
    Some((name, labels, v))
}
```
Rebuild a `Reading` from pin_volts/pin_amps so the same widgets and the same local `Lifecycle` run in every mode.

**(c) Tail the CSV.** Service default `/var/log/astral-watch/gpu-pins.csv`; on torch today `~/tmp/gpu-pins.csv`. Poll `stat()` every 500 ms; reopen when the inode changes or the size shrinks (rotation is a rename to `.1`); read only appended bytes; parse the 17 columns (`alerts` may be RFC-4180 quoted; unreachable rows have 16 empty fields and a message in `alerts`); freshness = now − parsed local timestamp (use `chrono::NaiveDateTime` + `Local`, or simply the file mtime). No `notify` crate needed.

**Recommendation — one `PinSource` with auto-selection, re-evaluated every 10 s:** priority `exporter` (authoritative: it carries the service's debounced `alert_active` and adds zero bus traffic) → `i2c` (when `detect_bus` is `Found`; `PermissionDenied` becomes a rendered hint) → `csv` (only if a configured path is fresher than 5 s) → `Unavailable(reason)` placeholder. Config: `[pins] source = "auto" | "i2c" | "exporter" | "csv"`, `exporter = "127.0.0.1:9942"`, `csv = "…"`, `interval_ms = 500`. Run the local `Lifecycle` (policy from `astral_watch::config::load(None)`) on the `Reading` stream in all modes; in exporter mode additionally OR-in the service's `alert_active` flags and show a small "svc" badge. Thread shape (opsTui is tokio-based; the reads are blocking ioctls):

```rust
pub struct PinSample { pub at: Instant, pub reading: Option<Reading>, pub status: PinStatus, pub alerts: Vec<Alert>, pub events: Vec<Event>, pub bus: Option<u32>, pub source: SourceKind }
// std::thread::Builder::new().name("pins-sampler") loop:
//   read_reading(bus, CHIP_ADDR) → evaluate(&r, &cfg.thresholds) → lifecycle.observe(Instant::now(), &conds)
//   tx.send_replace(sample)   // tokio::sync::watch::Sender<PinSample>
//   misses >= REDETECT_AFTER → redetect_card(CHIP_ADDR, &pci)
```
Keep `Reading` history (300 samples like the TUI) in the component, not the sampler.

## 3. Dependency mechanics

```toml
[dependencies.astral-watch]
git = "https://github.com/mbeaman/astral-watch"
rev = "dce7eee77676268c66b3624c7a2870ed9d84eb9c"   # or tag = "v0.8.0" once cut
default-features = false                            # today a no-op: nothing is default
# never features = ["tui"] (ratatui 0.29 + crossterm 0.28 would be duplicated next to 0.30/0.29 — it compiles, but doubles the TUI stack and its panic hooks) and not "safety".
```
For day-to-day work use `[patch."https://github.com/mbeaman/astral-watch"] astral-watch = { path = "../astral-watch" }` in opsTui's workspace `Cargo.toml` (or `.cargo/config.toml`) so the git rev stays the committed truth while the sibling checkout is used locally. MSRV: astral-watch declares `rust-version = "1.85"` (uses `LazyLock`); toolchain is 1.95; sysinfo 0.39.6 declares MSRV 1.95 — if opsTui pins an MSRV CI job it must be ≥ 1.95 or avoid sysinfo. Graph cost of linking the lib today: 70 crates, because `clap`, `signal-hook`, `ureq` (+ rustls, 37 crates), `chrono`, `serde_json`, `toml 0.9` are non-optional. Library modules also `eprintln!` (`i2c.rs:294` latch message, `exporter.rs:46`, `logger.rs:107`, `notify.rs:313/319`) — on a fullscreen TUI these scribble over the alternate screen, so opsTui must `dup2` stderr to a log file at startup (libc/rustix, or route through a log pane) until fixed upstream.

**Small upstream PRs that make integration clean** (in priority order): (1) tag/release v0.8.0 with the advisory + block-read changes and bump `version`; (2) `[features] default = ["cli"]; cli = ["dep:clap", "dep:signal-hook"]`, `notify = ["dep:ureq", "dep:serde_json"]`, `[[bin]] required-features = ["cli"]` — a lib consumer with `default-features = false` drops ~45 crates; (3) replace library `eprintln!` with the `log` facade (or return the `Access` decision); (4) add `i2c::Sampler { bus, addr, pci, misses, access }` with `fn sample(&mut self) -> Sample { reading: Result<Reading>, plausible, redetected: Option<u32> }` so the `read → plausible? → misses → redetect_card` loop lives in one place instead of being copied by main.rs, tui.rs, safety.rs and opsTui; (5) `Lifecycle::active() -> impl Iterator<Item = (Condition, &str detail, Instant since)>` so a consumer can render current state without replaying events; (6) `Metrics::snapshot()` returning a typed struct (and a `serde` feature) so the exporter can also serve JSON — cheaper for opsTui than text parsing; (7) `Thresholds`/`AlertPolicy` `Serialize`; (8) chrono is already only in bin/tui/safety — nothing to remove from the hot path, but `Local::now()` per sample in `run()` could move behind the CSV sink.

## 4. Sensors source (torch inventory, verified read-only)

hwmon on this machine (`/sys/class/hwmon/hwmonN/name`; numbering is not stable across boots — key sensors by `name` + resolved device path, e.g. `k10temp@0000:00:18.3`, `nvme@nvme0`): hwmon0/1/2 `nvme` (nvme2 @ 7b:00.0: Composite 50.85 °C, Sensor 1, Sensor 2; nvme0 @ 02:00.0: same three; nvme1 @ 0e:00.0: Composite only) with `temp1_crit` 84.85/87.85/79.85 °C, `temp1_max` 81.85/83.85/74.85 °C, and **bogus sentinels** `temp2_max = temp3_max = 65261850` (filter `_max > 1_000_000`); hwmon3 `mt7925_phy0` temp1 52 °C (no label); hwmon4 `k10temp` (`Tctl` 59.25, `Tccd1` 58.1, `Tccd2` 56.6 — no `Tdie`; Tctl is the fan-control temp, Tccd* per-CCD; no thresholds exported); hwmon5/6 `r8169_0_b00:00` / `r8169_0_c00:00` NIC temps 61 / 58.5 °C with `temp1_max` 120 / 110 °C; hwmon7 `asus` (eeepc-wmi) — **no attributes at all**; hwmon8/9 `spd5118` DIMM temps 43.75 / 42.25 °C (`temp1_max` 55 °C, `temp1_crit` 85 °C, `*_alarm` flags) on `i2c-8` PIIX4 at 0x51/0x53. No `fan*`, `in*`, `power*` or `pwm*` files anywhere, and **no `/sys/class/thermal/thermal_zone*`** exist. Units (kernel hwmon sysfs ABI): temp m°C, fan RPM, in mV, curr mA, power µW, energy µJ, pwm 0–255; a read error/`-ENODATA` means "unavailable this sample". Walker shape:

```rust
struct Sensor { key: String, chip: String, label: String, kind: Kind, path: PathBuf, max: Option<f64>, crit: Option<f64> }
// for hwmonN: chip = read("name"); for f in "temp*_input"|"fan*_input"|"in*_input"|"power*_input":
//   label = read(stem + "_label").unwrap_or(stem); max/crit from stem + "_max"/"_crit" (drop > 1e6 m°C)
//   value: temp/1000.0 °C, fan as-is RPM, in/1000.0 V, power/1e6 W
```
Sampling: hwmon temps at 1 Hz (nvme `temp*_input` issues an NVMe SMART Get-Log-Page; spd5118 is an SMBus read on the PIIX4 bus — both cheap but not worth > 2 Hz; k10temp is an SMN read). Optional `sysinfo::Components` (0.39.6: `Component::{label() -> &str, temperature() -> Option<f32>, max(), critical(), id()}`, Linux reads hwmon) covers temps only — a hand-rolled walker is smaller than sysinfo's `component` feature and also yields future fans/PWM if an `nct67xx` driver ever appears.

**RAPL**: `/sys/class/powercap/intel-rapl:0` (`name` = `package-0`) and `intel-rapl:0:0` (`core`) exist (the intel_rapl driver serves AMD Zen), but `energy_uj` is **0400 root-only** on torch (kernel commit 949dd0104c49 "powercap: restrict energy meter to root access", 5.10, CVE-2020-8694/Platypus); `max_energy_range_uj = 65532610987` (≈65.5 kJ wrap) is world-readable; no `power_uw`/`constraint_*` on AMD. The perf alternative (`/sys/bus/event_source/devices/power/events/energy-pkg`, event 0x02, scale 2^-32 J) is blocked too: `perf_event_paranoid = 4`. Options: a udev rule `SUBSYSTEM=="powercap", KERNEL=="intel-rapl:*", RUN+="/bin/chmod 0440 /sys%p/energy_uj", GROUP="…"` (sudo once), a tiny root helper, or render "RAPL: needs root" — pick in config. Conversion: `watts = (Δenergy_uj mod max_energy_range_uj) / Δt_s / 1e6`, sample at 1 Hz.

**PSI**: `/proc/pressure/{cpu,memory,io}` are 0666, `irq` is absent (needs CONFIG_IRQ_TIME_ACCOUNTING). Format `some avg10=… avg60=… avg300=… total=<µs>` / `full …` (cpu `full` is always 0 at system level). Show `avg10` as % and compute instantaneous stall % = Δtotal_µs / Δt_µs × 100 at 1 Hz. `procfs 0.18.0` offers `CpuPressure::current()` / `MemoryPressure` / `IoPressure` (fields `some`, `full: PressureRecord{avg10, avg60, avg300, total}`) — use `default-features = false` (default pulls chrono + flate2) or hand-parse (10 lines).

**CPU frequency**: cpufreq `amd-pstate-epp`, `scaling_cur_freq` (kHz, e.g. 5553148) and `cpuinfo_avg_freq` are world-readable; use those rather than `/proc/cpuinfo`.

**NVML overlap**: GPU temp (45 °C, memory temp N/A on this driver), fan (30 %), power (107 W of 600 W), clocks and PCIe link come from NVML — `nvml_wrapper::Device::{temperature(TemperatureSensor::Gpu) -> u32 °C, fan_speed(idx) -> u32 %, num_fans(), power_usage() -> u32 mW, enforced_power_limit() -> u32 mW, utilization_rates() -> Utilization{gpu, memory}, memory_info(), clock_info(Clock), current_pcie_link_gen/width(), pcie_throughput(PcieUtilCounter) -> KB/s, performance_state(), current_throttle_reasons(), total_energy_consumption() -> u64 mJ, pci_info()}` (signatures verified in the local 0.12.1 source). The sensors component must not duplicate these: define one `SensorReading { key, chip, label, kind, value, unit, warn, crit, at }` and let the GPU source publish its readings through the same bus; the astral-watch component's "device header" should read NVML from the shared GPU source instead of spawning `nvidia-smi` every 1.5 s like tui.rs. Note `pcie_link` from sysfs (`current_link_speed/width` under `/sys/bus/pci/devices/0000:01:00.0/`) needs no NVML and matches tui.rs.

## 5. Size-class plan for the pins component and the alarm overlay

Every tier renders from the same `PinsModel { reading, live, hist: [VecDeque<f64>;6], peaks, watts_hist, peak_watts, active: Vec<(Condition, String, Instant)>, log }`; tiers are chosen by the inner `Rect` (cols × rows), not by grid units, so the same component fits any grid.

- **1x1 (≥ 10×3)**: big total watts (`tui-big-text` when ≥ 14×5, else bold) + balance badge `1.54×` coloured by the same idle/NORMAL/WARN/ALARM rule as the TUI gauge + a 1-cell alert glyph (`!` red / `▲` amber / `?` telemetry lost / `·` ok). Stale ⇒ dim + `STALE`.
- **2x1 (≥ 20×3)**: six 2-col vertical mini bars (`▁▂▃▄▅▆▇█` eighth-blocks for sub-row resolution) scaled to 10 A, coloured per pin like `pin_color`, a `┄` at 9.2 A when rows ≥ 4, and `Σ 111 W` right-aligned.
- **4x2 (≥ 40×8)**: full-height bars with peak caps and numeric `8.2`/`p1` rows, plus a `LineGauge`/`Gauge` balance row titled `balance hi/lo · alarm >1.5×` and a totals line `9.2 A · 111 W · pins 12.06–12.08 V`.
- **6x3 (≥ 60×14)**: adds the watts `Sparkline` (last 300 samples) and a 3–5 line alert log (newest at bottom, red/amber/green like `sample()`), and the active-alert banner row inside the component.
- **Full page**: astral-watch tui parity — device header (NVML from the shared GPU source + sysfs PCIe link), Braille trend `Chart` of six pins with the 9.2 A y-max rule, balance gauge, watts sparkline, scrollable log with `Scrollbar`, pause/reset-peaks/rate/zoom keys, multi-card tabs via `discover_cards`-style enumeration (bytewise probe per NVIDIA bus, dedupe by PCI id).

**Alarm overlay**: opsTui keeps an app-level `AlertBus` (`tokio::sync::broadcast` or a `Vec` in the shell state) that any component feeds with `AppAlert { source: "pins", severity: Critical|Warning|Info, title, detail, since }`. The pins sampler maps `Event::Raised` for `Overload|Disconnected|Imbalance` → Critical (top-of-screen 1-row banner, red bg, `SLOW_BLINK`, drawn last in the frame over every page, plus a toast in the corner for 8 s), `ImbalanceAdvisory` → Warning (amber toast only, no banner, no blink), `TelemetryLost` → Info (grey status-bar chip), `Repeated` → re-flash the toast, `Resolved` → green toast "OVERLOAD clear after 5m02s" for 8 s and banner removal. Because the lifecycle already debounces (3-of-5 samples ⇒ 1.5 s at 0.5 s), the overlay must not add its own hysteresis; it should key on `Condition`, not on per-sample `Alert`s, so it never flickers. Sampling continues while the component is hidden, so the banner appears on any page. Do not enable astral-watch's `notify` transports from opsTui — the service (when installed) already pages; opsTui is the on-screen surface.

## Recommendations

- **Depend on astral-watch as a pinned git dependency (rev dce7eee… or a future tag v0.8.0) with `default-features = false`, and use a workspace `[patch]` to the sibling checkout for local development; never enable the `tui` or `safety` features.** — The crate is not on crates.io (verified: cargo search, crates.io API 404, docs.rs 404). HEAD is 3 commits past v0.7.0 with public-API changes (advisory severity, block-read path, renamed read_raw_from→read_raw_bytewise) while Cargo.toml still says 0.7.0, so only an explicit rev/tag is unambiguous. The `tui` feature would pull ratatui 0.29 + crossterm 0.28 next to opsTui's 0.30/0.29 — it compiles but duplicates the whole TUI stack and its panic hooks.
  - alternatives: Path dependency only (breaks reproducible builds from a fresh clone); publish astral-watch 0.8.0 to crates.io first (cleanest long-term; blocked until the user publishes); vendoring the four modules (loses upstream fixes).
- **Implement a `PinSource` with auto-selection in the order exporter → direct i2c → CSV tail → Unavailable, re-probed every 10 s, with a config override, and run astral-watch's `Lifecycle` locally on the Reading stream in every mode using `config::load(None)`.** — The exporter is authoritative (carries the service's debounced alert state, adds no bus traffic) but is not running on torch today; direct i2c works now (user in i2c group, /dev/i2c-* 0660) and is proven safe alongside the root logger; the CSV is a live fallback (~/tmp/gpu-pins.csv). Running the same Lifecycle everywhere keeps alarm semantics identical across sources and honours the same thresholds file the service reads.
  - alternatives: Direct i2c only (simplest, but double bus traffic once the service is installed and no service alert state); exporter only (nothing to show until the user installs the service); CSV only (0.5–1 s lag, rotation handling, root-owned file).
- **Sample on a dedicated std thread publishing `PinSample` through `tokio::sync::watch`, at 500 ms when the component is visible and 1 s otherwise, never stopping while opsTui runs.** — Reads are blocking ioctls that busy-poll in the kernel (~4 ms block / ~33 ms bytewise); a watch channel gives the renderer the latest sample without queue growth; continuous sampling is what makes the cross-page alarm overlay work.
  - alternatives: `tokio::task::spawn_blocking` per sample (more overhead, harder to keep the Access latch and Lifecycle state together); stop sampling when hidden (loses the alarm guarantee).
- **Redirect stderr (dup2 to a log file or an in-app log pane) at opsTui startup, and send an upstream PR replacing library `eprintln!` calls with the `log` facade plus feature-gating `cli` (clap, signal-hook) and `notify` (ureq, serde_json).** — i2c.rs prints `# i2c-N @ 0x2b: using block read` on latch, and exporter/logger/notify print on failures — on an alternate-screen TUI these corrupt the display. The unconditional deps make a lib consumer pull 70 crates including rustls (37 under ureq).
  - alternatives: Accept the graph cost and only redirect stderr; vendor the modules.
- **Hand-roll the Prometheus text parser (~50 lines) and the CSV tailer (stat-poll + inode check) instead of adding prometheus-parse or notify.** — prometheus-parse 0.2.5 depends on chrono, regex, itertools and once_cell for a format subset that is trivial here (`name{k="v"} value`, `+Inf`); CSV rotation is a rename, detectable by inode/size checks at 500 ms.
  - alternatives: prometheus-parse 0.2.5; notify 9.0.0-rc.5 for inotify-driven tailing.
- **Build the sensors source as a hand-rolled hwmon walker keyed by chip name + device path, plus PSI and (privilege-gated) RAPL, and expose one `SensorReading` shape that the GPU/NVML source also publishes.** — hwmon on torch has only temps (k10temp, 3×nvme, 2×spd5118, 2×r8169, mt7925) with no fans/voltages/power; hwmonN numbers are unstable across boots; nvme `temp2/3_max` carry a 65261850 sentinel; RAPL energy_uj is root-only (0400) and perf_event_paranoid=4 blocks the perf path; sysinfo's Components covers temps only and pulls the `component` feature.
  - alternatives: sysinfo 0.39.6 `Components` (temps only, MSRV 1.95); lm-sensors/libmedium bindings (libsensors not installed); procfs 0.18 for PSI (fine with default-features=false).
- **Size tiers chosen by inner Rect (cols×rows) rather than grid units: 1x1 ≥10×3 watts+balance badge; 2x1 ≥20×3 six eighth-block mini bars; 4x2 ≥40×8 bars+numbers+balance gauge; 6x3 ≥60×14 +sparkline+log+banner; full page = tui.rs parity with NVML from the shared GPU source instead of an nvidia-smi subprocess.** — Matches the user's grid goal while keeping one model; tui.rs's constants (AMPS_CEILING 10, HISTORY 300, LOG_CAP 200, colour thresholds 9.2/7.82 A, balance WARN 1.33/ALARM 1.5, idle below min_load) are reused verbatim for parity.
  - alternatives: Fixed grid-unit → layout mapping (breaks on unusual terminal sizes).
- **Alarm overlay driven by lifecycle `Condition` edges: Overload/Disconnected/Imbalance → red blinking top banner + toast on every page; ImbalanceAdvisory → amber toast only; TelemetryLost → status-bar chip; Resolved → green 8 s toast. No extra hysteresis in the overlay, and no astral-watch notify transports from opsTui.** — The Lifecycle already debounces (3-of-5 samples) and freezes on telemetry loss; layering more hysteresis would delay real alarms; the TUI's own red-vs-amber split exists to avoid permanent false alarms on structurally imbalanced idle cards (the CSV on torch shows a persistent 1.54× advisory at 9.2 A total).
  - alternatives: Per-sample `Alert` driven overlay (flickers); desktop notify-send from opsTui (double-pages when the service is installed).

## Risks

- **API drift: opsTui written against HEAD (Alert::ImbalanceAdvisory, CONDITIONS len 5, read_raw_bytewise) will not compile against tag v0.7.0, and the crate version number does not distinguish them.** → Pin `rev` in Cargo.toml; ask upstream to bump to 0.8.0 and tag; add a CI job in opsTui that builds against the pinned rev only.
- **astral-watch is not on crates.io, so opsTui cannot be published to crates.io (git deps are rejected) and `cargo install` from a clone must keep network access to GitHub.** → Treat opsTui as GitHub-installed for now; publish astral-watch 0.8.0 first if crates.io publication of opsTui is ever wanted.
- **Library `eprintln!` calls (i2c.rs:294 latch message, exporter.rs:46, logger.rs:107, notify.rs:313/319) corrupt the alternate-screen TUI.** → dup2 stderr to a log file at startup (or capture into a log pane); upstream PR to use the `log` facade.
- **Bus contention with the root `astral-watch log` instance (PID 6755, 0.5 s, probably bytewise): extra kernel busy-poll time and occasional EIO on either side.** → Kernel per-adapter lock makes every SMBus transaction atomic (verified in i2c-core-smbus.c / nv-i2c.c), so data cannot be corrupted; keep opsTui at ≥ 0.5 s, rely on Lifecycle's TelemetryLost freeze, and prefer the exporter once the service is installed.
- **Deeply idle GPU: the MCU answers zeros → `read_reading` returns an implausible Reading (not an error); `detect_bus` returns NoTelemetry at startup.** → Mirror main.rs: retry detection every 5 s, render 'waiting for telemetry (GPU idle?)', feed TelemetryLost into the Lifecycle so no false all-clear is emitted.
- **Linking the lib pulls clap, signal-hook, ureq+rustls, chrono, serde_json, toml 0.9 (70 crates); toml 0.9 duplicates opsTui's toml 1.1.** → Accept for the first arc; upstream `cli`/`notify` features with `default-features = false` later.
- **RAPL package power is unavailable unprivileged (energy_uj 0400; perf_event_paranoid=4).** → Render 'needs root' by default; offer a documented udev rule or a root helper as opt-in; never require sudo for opsTui itself.
- **hwmon numbering (hwmon0..9) changes across boots; nvme temp2/3_max sentinel 65261850 and asus hwmon with zero attributes would produce garbage thresholds or empty chips.** → Key sensors by chip name + resolved device path; drop `_max/_crit` > 1e6 m°C; skip chips with no `*_input` files.
- **If opsTui also calls `exporter::spawn` on 127.0.0.1:9942 while the service does, bind fails; if it binds first, the service's export mode fails fast.** → Do not spawn the exporter from opsTui by default; if added, use a different port and make it opt-in.
- **Enabling astral-watch's `tui` feature drags in ratatui 0.29 + crossterm 0.28 alongside 0.30/0.29 and a second `ratatui::init()` panic hook.** → Never enable it; copy rendering ideas from tui.rs (constants and colour rules) instead.
- **CSV mode reads a root-owned file whose timestamps are local naive time and whose rotation renames the file.** → Check inode/size on every poll, reopen on change, parse with chrono Local, and treat > 5 s age as stale.
- **The advisory imbalance at idle (1.54× at 9.2 A total in the live CSV) would be a permanent amber state on this card.** → Follow the TUI's rule: advisories are amber, never blink, never trigger the red banner; show them in the log and a small chip only.
