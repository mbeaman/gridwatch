# gridwatch

A modular, themeable ops dashboard for the terminal — a grid of components that each render from a 1x1 tile to full screen, in themes like `retrowave`, `modern` and the rain-lit `matrix`, reproducing the behaviour of htop, nvtop and [astral-watch](https://github.com/mbeaman/astral-watch) alongside network, audio-visualizer and Winamp-style now-playing tiles. Rust + ratatui 0.30, built for a single Linux workstation first.

**Status: v0.9.0 in progress, nothing tagged yet.** Everything below works; the
tags wait on rows only a person can take (a real terminal, a running game, live
i2c — [`docs/PERFORMANCE.md`](docs/PERFORMANCE.md) lists them). Nine arcs so far:
the store, layout engine and theme system; **htop**, **nvtop** and
**astral-watch pins** parity down to their formulas; **network**, **audio**,
**sensors** and a **Winamp-style now-playing** tile; journal record/replay,
in-app layout editing, `[[rules]]` alerts, process actions behind a confirm
line, and an **exec plugin API** so a tile can be a program in any language.
[`docs/ROADMAP.md`](docs/ROADMAP.md) has what is left.

## Run it

```sh
cargo install --git https://github.com/mbeaman/gridwatch   # or, from a clone:
cargo run --release                 # live: the Overview against this machine
cargo run --release -- run --demo   # synthetic data, no hardware needed
cargo run --release -- run --demo --theme matrix   # the rain-lit showcase theme (V re-lights, L locks lit)
cargo run --release -- run --no-effects            # no theme effects, no rain (P20)
cargo run --release -- shot --format ansi --size 250x70 --theme retrowave
cargo run --release -- run --record session.jsonl      # journal every message (tables off; --tables on, --record-input)
cargo run --release -- run --replay session.jsonl --speed 4   # replay it; nothing downstream can tell
cargo run --release -- shot --replay session.jsonl --at 30 --format svg > frame.svg
cargo run --release -- keys                                  # the metric catalogue (docs/KEYS.md)
cargo run --release -- component list                        # every component's tiers (docs/COMPONENTS.md)
cargo run --release -- config default > ~/.config/gridwatch/config.toml
cargo run --release -- doctor       # every capability with a reason and a fix (+ the live probes; --offline skips them)
cargo run --release -- config check --theme phosphor-green   # the two files, then the theme's warnings and WCAG contrast report
cargo run --release -- keybindings                           # every key (docs/KEYBINDINGS.md)
cargo run --release -- theme import ~/.config/alacritty/theme.toml -o mine.toml   # alacritty, wezterm or base16 → a theme
```

Not on crates.io: gridwatch depends on astral-watch by git revision, and
crates.io forbids git dependencies. `cargo install --git` is the supported
path until that changes.

Keys: `?` shows them all; `hjkl` moves focus, `Enter` gives the keys to a tile
and `Esc` takes them back, `z` zooms, `t` cycles themes, `e` edits the layout,
`q` quits. The full list — global and per tile — is
[`docs/KEYBINDINGS.md`](docs/KEYBINDINGS.md), generated from the same table
that draws the key bar, so it cannot drift.

## What is here today

Ten tiles, seven themes, and a plugin API. Every tile renders from an 8×3 chip
to a full screen; `gridwatch component list` prints the tier ladder for each.

- **`htop`** — htop 3.4.1's meters with its formulas verbatim (guest subtracted,
  `cached = Cached + SReclaimable − Shmem`, iowait counted as idle), gradient
  core bars grouped into real CCD blocks from sysfs `die_id`, per-CCD frequency
  and `Tccd`, load, tasks and PSI, the top-N process table, and — zoomed — the
  full interactive one: search, filter, tree, tags, follow, thread toggles, the
  F-key bar, and **kill / renice / affinity / ioprio** behind a confirm line and
  a `readonly` flag.
- **`gpu`** — nvtop 3.2.0's header, a 20 ms board-power trace, ten-minute
  braille charts of util / VRAM / temperature / power / clock / effective load,
  the GPU-Z spec column, and the GPU process table joined with the cpu scan.
  Over nvml-wrapper on its own thread at ≈ 4.3 ms of NVML time per second,
  never `pcie_throughput`, and **never a GPU client itself**. Falls back to
  `nvidia-smi` when the library will not load.
- **`pins`** — per-pin 12V-2x6 amperage through
  [astral-watch](https://github.com/mbeaman/astral-watch)'s own library
  (exporter or direct i2c, auto-selected): six bars with peak caps and the
  9.2 A limit, the balance gauge, the watts trend and the alert log. Its
  overload alerts raise a **banner on every page**, and the thresholds are
  astral-watch's own, so what you see is what the service would send.
- **`net`** — every interface's rates and link state with rx/tx sparklines, the
  default route and resolvers, latency probes over an **unprivileged** ICMP
  socket, and the connection table with the process behind each socket where
  the kernel lets a normal user read it.
- **`audio`** — the default sink's monitor through a supervised `pw-record`
  child, a cava-style dual-FFT spectrum with Winamp or cava ballistics, an
  oscilloscope and stereo VU — animating at 30 fps (60 opt-in) **only while
  there is sound**, and killing the child ten seconds after you look away.
- **`winamp`** — the MPRIS player in classic-skin form: marquee, big elapsed
  digits, transport row, album art as half-blocks, and the spectrum borrowed
  from the audio source.
- **`sensors`** — every hwmon chip hottest-first with the chip's own
  thresholds, plus RAPL package power, PSI and the GPU's row.
- **`alerts`, `clock`, `sources`** — the last showing every source's state,
  generation, age, drops and restarts.
- **`[[rules]]`** — any metric becomes an alert: an operator, a hold before it
  raises and one before it clears, label globs (`sensor.temp_c{nvme*:Composite}`
  is one alert per drive), and a threshold that can be **another metric**.
- **Plugins** — a tile can be a program in any language speaking JSON lines
  over a pipe: no shell, resource caps, three strikes, and a view *tree* rather
  than cells, so a plugin cannot break your theme.
  [`docs/PLUGINS.md`](docs/PLUGINS.md) explains it in 140 lines of Python.
- **Themes** — `modern`, `retrowave`, `mono`, `terminal`, `phosphor-green`,
  `phosphor-amber`, and the showcase `matrix`, whose rain *prints* the
  dashboard rather than being drawn over it. Components never name a colour or
  a glyph, which is why one render path serves all seven.
  `gridwatch theme import` converts an alacritty, wezterm or base16 scheme.

It is built for one workstation and says so: `gridwatch doctor` prints every
capability with the reason it is missing and the fix, and a tile whose source
cannot work shows that instead of pretending.
